# 로컬 개발 환경 실행 방법

JDK 21, Docker Desktop, Python 3.10 이상이 필요합니다. 가장 빠른 메인 경로 실행은 저장소 루트에서 다음 순서로 합니다.

```sh
./mvnw package
bash scripts/monitoring.sh up
bash scripts/monitoring.sh demo --rate 1 --seconds 1 --errors
bash scripts/monitoring.sh verify
bash scripts/monitoring.sh status
```

`demo`는 `/api/v1/messages` 접수부터 업체 웹훅, 최종 이력, 1차 성공 과금 대상, 고객 웹훅까지 확인합니다. `--errors`를 주면 1차 HTTP 실패 건도 확인합니다. Grafana는 [메인 경로 통합 관제](http://localhost:13000/d/messaging-overview)에서 열고, 상세 화면과 검증 범위는 [모니터링 안내](19-그라파나-대시보드-실행과-PPT-항목-대응.md)를 참고하세요. `bash scripts/monitoring.sh stop`은 컨테이너만 정지하고 볼륨은 유지합니다.

독립 로컬 환경은 `.env.example`을 `.env`로 복사하고 다음 명령으로 준비합니다. `init-policy`는 테스트 고객의 메시지 TPS·월 Quota 정책을 Redis에 채웁니다.

```sh
bash scripts/local.sh infra
bash scripts/local.sh init-db
bash scripts/local.sh init-policy
bash scripts/local.sh build
bash scripts/local.sh run messaging-api
```

통신사 Sender는 `MSG_HTTP_CARRIER`, `MSG_HTTP_BASE_URL`, `MSG_HTTP_NOT_OUR_CARRIER_CODES`, `MSG_HTTP_TPS_EXCEEDED_CODES`를 각각의 실행 환경에 지정하고 `bash scripts/local.sh run messaging-carrier-http-sender`로 띄웁니다. 하나의 JAR을 통신사별 포트·토픽·소비 그룹으로 분리합니다. 나머지 AP도 `bash scripts/local.sh run <module>`로 실행할 수 있습니다. 운영 URL과 TCP 규격은 실제 업체 계약에 맞춰 설정해야 합니다.

CDC 참조 캐시를 따로 확인할 때는 `bash scripts/local.sh cdc`와 `bash scripts/local.sh run messaging-reference-cache`를 사용합니다. 계약 데이터는 Redis 우선·누락 시 PostgreSQL로 조회하고, 전화번호 통신사 Redis 매핑이 없으면 SKT부터 시도합니다. 상세는 [CDC 캐시](52-계약과-번호-통신사-CDC-캐시.md)를 참고하세요.

Java 검증은 `bash scripts/test-java.sh unit` 및 `bash scripts/test-java.sh integration`입니다. 통합 테스트는 별도 Docker Compose 프로젝트를 만들고 시험 후 컨테이너를 내리며 볼륨을 삭제하지 않습니다.
