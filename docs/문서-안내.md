**번호순으로 전부 읽을 필요는 없습니다.** 현재 설계·진행 상황을 이해하려면 아래 핵심 5개를 순서대로 읽으면 됩니다. 나머지는 작업할 때 찾는 상세 설명 또는 당시의 설계·검증 기록입니다. 번호는 작성 순서이며 중요도나 읽는 순서가 아닙니다.

## 3. 평소에는 읽지 않아도 되는 기록

다음 문서는 장애 재현, 성능 비교, 과거 결정 이유를 찾을 때 필요합니다. 원시 결과를 해석하는 조건·실패 기록이 있어 삭제하지 않습니다. **전부 읽어야 현재 시스템을 이해할 수 있는 필수 문서가 아닙니다.**

| 기록 묶음 | 문서 번호·현재 참고점 |
|---|---|
| 초기 개발 순서·단계별 설명·논의 경과 | 02·05·08. 현재 정책·순서는 00·01·04로 통합 |
| 고객 통지·완료 정리의 초기 제안 | 10·11. 현재 정책은 00·35, 현재 HTTP 계약은 31 |
| 초기 성능 계획·계측·모니터링 현황 | 13·14·18. 현재 시험 기준은 41·48, 화면 연결 범위는 19 |
| 초기 접수 성능 비교·100 TPS 적체 | 16·17·20·21·22. 당시 병목과 채택 설정의 근거, 현재 Pod 성능 아님 |

| 이전 완료 보관 정책·DDB 최소화 검토 | 32·33·34. 영구 완료 META·별도 FINAL·33회 등은 이전 구조, 현재는 35·36 |
| 전체 흐름·즉시 인계·정리 성능 비교 | 37·38·39·40. 재현·비교용 기록 |
| 실제 종료·저장소 장애 시험 | 42·43·44·45·47. 현재 대응 요약은 09, 실제 시험 조건은 각 기록 |

[검증 결과 JSON](검증-결과/)은 실행 도구·조건·수치·소스 지문을 추적하는 자료입니다. 일반 설명처럼 순서대로 읽지 않아도 됩니다. 공식 문서 링크와 대안 비교가 있는 ADR도 필요할 때 해당 결정만 봅니다.

## 4. 앞으로 문서를 늘리는 기준

- 기능을 고치면 해당 주제 문서를 갱신합니다. 커밋마다 새 진행 문서를 만들지 않습니다.
- 진행 상황·미완료 목록은 01, 정책은 00, 호출 흐름은 04에서 각각 관리합니다. 같은 설명을 여러 파일에 복사하지 않습니다.
- 새 문서는 독립적인 연동 계약·운영 절차·중요한 설계 결정이 생길 때 추가합니다.
- 시험 수치와 실패 원인은 검증 결과에 보존하고, 설명 문서에는 결론·조건·근거 링크를 남깁니다.
- 정책 변경 시 현재 문서 본문을 고칩니다. 예전 결론 아래에 정정 문구만 계속 붙이지 않습니다.

이번 정리는 파일 경로와 기존 기록을 유지했습니다. 문서 파일 수를 줄인 작업이 아니라, **기본 읽기 경로를 5개로 줄이고 핵심 본문의 중복·이전 정책을 정리한 작업**입니다. 이전 원문은 Git 이력에서도 확인할 수 있습니다.
