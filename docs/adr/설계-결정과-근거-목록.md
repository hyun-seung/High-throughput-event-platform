# 설계 결정과 근거 목록

모두 읽을 필요는 없습니다. 특정 선택의 이유·대안·공식 근거가 필요할 때 해당 ADR을 봅니다. 현재 전체 동작은 [요구사항](../00-요구사항과-전체-설계.md)과 [Call Flow](../04-요청-접수부터-최종-결과까지의-전체-흐름.md), 현재 완료 후 멱등 정책은 ADR-022가 기준입니다. 아래 미작성 ADR 번호는 기록 후보이며 개발 전에 전부 작성해야 하는 목록이 아닙니다.

## 작성 형식

파일명은 `ADR-NNN-한글-제목.md`를 사용합니다. 상태는 `Proposed`, `Accepted`, `Superseded` 중 하나입니다.

```markdown
# ADR-NNN 제목

- Status: Proposed
- Date: YYYY-MM-DD

## 문제
## 검토한 대안
## 결정
## 선택 이유
## 장점과 제약
## 장애 상황
## 복구 방법
## 성능 영향
## 검증 방법
```

`검증 방법`에는 결정이 맞는지 확인할 자동 테스트, 장애 테스트, 메트릭을 적습니다. `선택 이유`에는 공식 문서의 URL·검토 버전·날짜와 프로젝트의 판단을 구분해 기록합니다. `장점과 제약`에는 보장이 성립하는 조건과 남는 실패 사례를 포함합니다. 요구사항이나 운영 설정이 미확정이면 `Proposed`로 남깁니다.
